## 一、部署定位

- 服务进程以**容器镜像**形态部署在**内网**，对内网调用方（Agent/CI/测试平台）提供唯一入口：`POST /v1/media-runs` 等 5 个 HTTP API。
- 音视频模拟数据（fixture）由内网侧控制：调用方通过 `artifact_ref` 引用，服务负责解码、上传与注入。
- 出向连接走公网：Pod ADB（EIP 临时地址）与 ACEP OpenAPI。**服务自身不暴露任何公网端口。**

```text
内网调用方(Agent/CI/测试平台)
    │ 仅内网 http://<内网地址>:8787
    ▼
┌─ Media I/O Harness 容器(0.0.0.0:8787,内网可达) ─┐
│  编排层(12 action)/状态机/fixture 管理           │
│  出向: → Pod ADB EIP:10001(push/forward 18080)   │
│        → ACEP OpenAPI(截图/设备管理)             │
│  卷: SQLite + reports/ + fixture staging         │
└──────────────────────────────────────────────────┘
```

### 明确排除

不做 TLS 终止、公网网关、域名、外部鉴权体系（API Key/OIDC）、CORS、限流。内网信任边界内沿用 `environment_ref` 即身份的既有语义；若内网环境混杂，可后置加静态 token 中间件，不进入本期。

## 二、镜像设计

### 2.1 基础镜像与分层

Python 运行时无第三方依赖（纯标准库），镜像只需系统工具：

```dockerfile
FROM python:3.12-slim

# ffmpeg: fixture 解码(I420/PCM)
# android platform-tools: adb(push fixture / forward 18080)
RUN apt-get update && apt-get install -y --no-install-recommends \
    ffmpeg android-sdk-platform-tools-common adb \
    && rm -rf /var/lib/apt/lists/*
# 注:Debian 的 adb 包名为 adb(android-sdk-platform-tools);构建时按发行版核对

# APK 产物随镜像分发(injector 含 vendored proxysdk;probe 为观察点)
COPY media-injector/app/build/outputs/apk/debug/app-debug.apk /opt/prismloop/apk/media-injector.apk
COPY media-probe/build-artifacts/prismloop-media-probe-debug.apk /opt/prismloop/apk/media-probe.apk
COPY src/ /opt/prismloop/src/
COPY config/ /opt/prismloop/config/

WORKDIR /opt/prismloop
EXPOSE 8787
VOLUME ["/opt/prismloop/data", "/opt/prismloop/reports"]
CMD ["python3", "-m", "src.media_server", "--provider", "pod-injector"]
```

### 2.2 镜像产物与构建前提

| 产物 | 进入镜像方式 | 说明 |
|---|---|---|
| `src/` | COPY | 纯标准库，无 pip install |
| injector APK | CI 构建后 COPY | `gradle :app:assembleDebug`，proxysdk aar 已 vendored |
| media-probe APK | CI 构建后 COPY | 诊断观察点 |
| ffmpeg / adb | apt 安装 | 运行时系统依赖 |

**禁止进入镜像**：AK/SK、STS token、Pod 地址、签名 URL（项目安全硬约束）。

## 三、进程装配改造（部署前置代码项）

当前 [media_server.py](../src/media_server.py) 非 `--demo` 模式直接退出。部署需新增 `--provider pod-injector` 装配路径：

| # | 改造项 | 内容 | 依赖 |
|---|---|---|---|
| P1 | 生产 bootstrap | 新增 `--provider pod-injector`：读取 env 部署配置，调用 `build_pod_injector_service` 装配（injector host/port、remote_root、push_fixture、wait_sleep=time.sleep） | 已有函数，纯装配 |
| P2 | `PodAdbSession`（ADB 生命周期） | 把 poc 脚本中的手工步骤下沉为服务内组件：`adb connect` → `am start` injector → `forward tcp:18080` → 心跳探活 `/status` | P1 |
| P3 | ADB 地址续租 | 公网 ADB 地址是临时的（TTL 3600s）。`PodAdbSession` 周期（建议 1800s）经 ACEP `pod_adb_enable` 重新解析地址并重连；forward 随重连重建 | P2 |
| P4 | APK 部署 | 首次连接时检查 injector/probe 是否已安装，缺失则 `adb install`（幂等） | P2 |
| P5 | 监听地址 | 部署环境变量 `PRISMLOOP_MEDIA_LISTEN_HOST=0.0.0.0`（代码已支持，仅改部署默认值/模板） | 无 |
| P6 | `/healthz` 路由 | media_http 增加：进程存活 + SQLite 可写 + injector `/status` 探活结果 | 无 |

### 部署环境变量（config 模板修订值）

```bash
PRISMLOOP_MEDIA_LISTEN_HOST=0.0.0.0
PRISMLOOP_MEDIA_LISTEN_PORT=8787
PRISMLOOP_STATE_DB_PATH=/opt/prismloop/data/media-runs.sqlite
PRISMLOOP_ARTIFACT_STORE_REF=tos/prismloop-media
PRISMLOOP_DEVICE_PROVIDER_PROFILE=volc/pod-raw-frame     # 主线:Pod 裸数据注入
PRISMLOOP_POD_ID=<Pod ID>                                # 目标云机(首期单 Pod)
PRISMLOOP_INJECTOR_PORT=18080
PRISMLOOP_ADB_REFRESH_SECONDS=1800
# 凭证(容器 Secret 注入,不入镜像不入 Git):
VOLC_AK=... / VOLC_SK=...   (acep.credentials_source=env)
```

现有 [media-harness.template.env](../config/media-harness.template.env) 指向已废弃的 `volc/client-external-frame` gateway 路线，实施 P1 时同步修订为上述值。

## 四、数据持久化

| 数据 | 路径（卷） | 保留策略 |
|---|---|---|
| 任务状态库 | `data/media-runs.sqlite` | 容器重启后 `queued` 任务保留；过期 `running` 按 §3.1 以 `worker_lease_expired` 进入 error |
| 证据输出 | `reports/`（截图/logcat/status JSON） | 按 retention policy；接 TOS ArtifactStore 后弱化为暂存 |
| fixture staging | `/tmp`（容器内） | 临时目录，run 结束即清理 |

## 五、运维约定

- **日志**：print → stdout 结构化日志；脱敏规则沿用架构文档 §七（Pod ID/AK/SK/签名 URL 不入日志）。
- **失败语义**：injector 不可达 → run 进入 `error`（`InjectorUnavailableError`），`PodAdbSession` 后台自动重连，恢复后新 run 正常；不自动重试旧 run（幂等键由调用方控制）。
- **单实例约束**：首期单服务进程 + 单 Pod（`device_leases` 互斥已内建）；多 Pod 是水平扩展项，不在本期。
- **验证清单**（部署后）：
  1. `/healthz` 200 且 injector=reachable；
  2. `GET /v1/media-capabilities?environment_ref=<ref>` 返回 verified 账本；
  3. 提交最小 MediaRunRequest（单视频注入 + 截图）走完 `queued → completed`；
  4. 重启容器后 SQLite 中历史 run 仍可查。
