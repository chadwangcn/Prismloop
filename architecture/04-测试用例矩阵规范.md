## 一、测试用例分层

### 1.1 优先级分层

| 优先级 | 覆盖范围 | 执行时机 | 通过率要求 |
|---|---|---|---|
| **P0 冒烟** | 核心 flow 正向(登录→首页→报告→反馈) | 每次构建 | 100% |
| **P1 功能** | 每个功能点的正常/空/错误/异步状态 | 每日回归 | ≥95% |
| **P2 边界** | 权限弹窗、弱网、Idempotency conflict、过期 Session | 每周回归 | ≥90% |
| **P3 负向** | 越权、跨面 token、无效 token、缺 Idempotency-Key | 发版前 | ≥85% |

### 1.2 测试类型分类

| 类型 | 说明 | 单端/双端 |
|---|---|---|
| 冒烟测试 | 核心 flow 正向 | 双端 |
| 功能测试 | 各功能点状态覆盖 | 单端 + 双端 |
| 边界测试 | 异常场景 | 单端 + 双端 |
| 负向测试 | 安全与权限 | 双端 |
| 协同测试 | 双端业务链路 | 双端 |
| 音视频测试 | 拍照/录音/扫码 | K1 单端 + 双端回传 |
| 物理按键测试 | K1 五键 | K1 单端 + 双端感知 |
| 压力测试 | 并发场景 | 双端配对 |

## 二、用例格式规范

### 2.1 YAML 用例结构

```yaml
# 用例元信息
case_id: GAPP-DUAL-001              # 必填,唯一标识
title: 家长端绑定 K1 设备             # 必填,简述
priority: P0                         # 必填,P0/P1/P2/P3
type: dual                           # 必填,single/dual
category: binding                    # 必填,功能分类
tags: [binding, smoke, dual-end]     # 可选,标签

# 拓扑配置
topology:
  guardian_pod: pod-guardian-01      # 双端必填
  k1_pod: pod-k1-01                  # 双端必填

# 前置条件
preconditions:
  - "APP 已安装并冷启动"
  - "用户会话处于 expired 状态"
  - "K1 设备已激活"

# 音视频注入(可选)
inject_assets:
  - type: video
    file: assets/qrcode-standard.mp4
    pod: k1_pod
    inject_method: adb_broadcast

# 测试步骤
steps:
  - pod: pod-k1-01
    method: mua                      # mua/sdk/adb
    action: "运行 K1 APP,完成设备激活"
    assert:
      - "APP 显示激活成功"
      - "设备状态为 provisioned"
    screenshot: true
  
  - pod: pod-guardian-01
    method: mua
    action: "扫描 K1 二维码,完成绑定"
    prereq: "K1 设备已激活"
    assert:
      - "Guardian APP 显示绑定成功"
    screenshot: true
  
  - pod: pod-k1-01
    method: poll_ui                  # 轮询 UI
    action: "等待 K1 显示绑定状态"
    check: "截图检测'已绑定 Guardian'文字"
    timeout_sec: 30
    interval_sec: 2
    screenshot: true

# 协同断言(可选)
dual_assertions:
  - type: dual_screenshot
    description: "双端截图绑定状态"
  - type: state_consistency
    fields: [device_sn, family_id, child_id]

# OutputSchema(可选,用于 MUA 结构化输出)
output_schema:
  Type: dict
  Fields:
    - Name: binding_success
      Type: boolean
      Required: true
    - Name: device_sn
      Type: string
      Required: true

# 预期结果
expected:
  binding_success: true
  device_sn: "<预定义的设备 SN>"

# 清理(可选)
teardown:
  - "清除会话"
  - "重置 K1 设备状态"
```

### 2.2 字段说明

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `case_id` | string | 是 | 唯一标识,格式 `GAPP-<TYPE>-<NUM>` |
| `title` | string | 是 | 简述 |
| `priority` | string | 是 | P0/P1/P2/P3 |
| `type` | string | 是 | single/dual |
| `category` | string | 是 | 功能分类 |
| `topology` | object | 双端必填 | Pod 配对 |
| `preconditions` | list | 否 | 前置条件 |
| `inject_assets` | list | 否 | 音视频注入配置 |
| `steps` | list | 是 | 测试步骤 |
| `steps[].method` | string | 是 | mua/sdk/adb/poll_ui |
| `steps[].assert` | list | 否 | 断言条件 |
| `dual_assertions` | list | 否 | 协同断言 |
| `output_schema` | object | 否 | MUA 结构化输出 |
| `expected` | object | 否 | 预期结果 |
| `teardown` | list | 否 | 清理操作 |

## 三、步骤执行方式

### 3.1 四种 method

| method | 接入 | 适用 | 示例 |
|---|---|---|---|
| `mua` | MUA OpenAPI | 复杂流程、UI 适应 | `method: mua` |
| `sdk` | 客户端 SDK | 精确事件(按键、点击、多点触控) | `method: sdk` |
| `adb` | ADB 公网直连 | 调试、简单操作 | `method: adb` |
| `poll_ui` | 截图轮询 | 等待异步状态 | `method: poll_ui` |

### 3.2 步骤示例

#### MUA 步骤

```yaml
- pod: pod-guardian-01
  method: mua
  action: "在 Guardian APP 中扫描 K1 二维码完成绑定"
  system_prompt: "你是 Guardian APP 的 QA 工程师"
  max_step: 30
  timeout: 60
  assert:
    - "显示绑定成功"
  screenshot: true
  output_schema:
    Type: dict
    Fields:
      - Name: binding_success
        Type: boolean
```

#### SDK 步骤(按键)

```yaml
- pod: pod-k1-01
  method: sdk
  action: "按 AI 键"
  sdk_call:
    interface: sendKeyCode
    keycode: 67
    action: down_up
    duration_ms: 100
  screenshot_after_ms: 500
  assert:
    - "语音助手浮层可见"
```

#### SDK 步骤(点击)

```yaml
- pod: pod-guardian-01
  method: sdk
  action: "点击登录按钮"
  sdk_call:
    interface: sendMouseKey
    x: 540
    y: 960
    action: down_up
  screenshot_after_ms: 300
```

#### ADB 步骤(调试)

```yaml
- pod: pod-k1-01
  method: adb
  action: "按音量+键"
  adb_command: "input keyevent 24"
  screenshot_after_ms: 300
```

#### poll_ui 步骤(轮询等待)

```yaml
- pod: pod-k1-01
  method: poll_ui
  action: "等待 K1 显示绑定状态"
  check:
    type: visual
    description: "截图检测'已绑定 Guardian'文字"
  timeout_sec: 30
  interval_sec: 2
  screenshot: true
```

## 四、断言机制

### 4.1 三层断言

| 层 | 来源 | 说明 |
|---|---|---|
| MUA 内置断言 | MUA Prompt 中要求判断 passed | 步骤级断言 |
| OutputSchema 结构断言 | 返回 JSON 后用 JSONPath 断言 | 字段级断言 |
| 截图视觉断言 | 截图与基线 diff | 视觉级断言 |

### 4.2 断言类型

| 类型 | 说明 | 示例 |
|---|---|---|
| `visual` | 截图视觉检测 | "验证登录按钮可见" |
| `state` | APP 状态检测 | "mCurrentFocus 为 LoginActivity" |
| `text` | 文本检测 | "显示'绑定成功'" |
| `json_path` | JSONPath 断言 | `$.binding_success == true` |
| `dual_screenshot` | 双端截图 | 双端同时截图 |
| `state_consistency` | 双端状态一致性 | device_sn 一致 |

### 4.3 断言示例

```yaml
assert:
  - type: visual
    description: "验证语音助手浮层可见"
    screenshot_after_ms: 500
    expected_element: "语音助手浮层"
  
  - type: state
    description: "验证 APP 进入 listening 状态"
    check: "adb shell dumpsys activity grep mCurrentFocus"
    expected: "com.lumi.guardian/.VoiceAssistantActivity"
  
  - type: json_path
    path: "$.binding_success"
    expected: true
  
  - type: dual_screenshot
    description: "双端截图绑定状态"
  
  - type: state_consistency
    fields: [device_sn, family_id, child_id]
```

### 5.1 协同场景矩阵

### 5.2 典型协同用例

#### 用例 1:绑定协同

```yaml
case_id: GAPP-DUAL-001
title: 家长端绑定 K1 设备,验证双端绑定状态一致
priority: P0
type: dual
category: binding
topology:
  guardian_pod: pod-guardian-01
  k1_pod: pod-k1-01
steps:
  - pod: pod-k1-01
    method: mua
    action: "运行 K1 APP,完成设备激活流程"
    assert: ["APP 显示激活成功"]
  
  - pod: pod-guardian-01
    method: mua
    action: "运行 Guardian APP,扫描 K1 二维码完成绑定"
    prereq: "K1 设备已激活"
    assert: ["Guardian APP 显示绑定成功"]
  
  - pod: pod-k1-01
    method: poll_ui
    action: "等待 K1 显示绑定状态"
    check:
      type: visual
      description: "截图检测'已绑定 Guardian'文字"
    timeout_sec: 30
    interval_sec: 2
    assert: ["K1 显示已绑定 Guardian"]
  
  - pod: pod-guardian-01
    method: mua
    action: "查询绑定列表,验证 K1 在列"
    assert: ["绑定列表包含 K1 设备"]
dual_assertions:
  - type: dual_screenshot
  - type: state_consistency
    fields: [device_sn, family_id]
expected:
  binding_success: true
```

## 六、单端用例矩阵

### 6.1 Guardian APP 单端用例

```yaml
case_id: GAPP-GUARDIAN-001
title: 登录后刷新 token,验证 growth-home 加载
priority: P0
type: single
category: auth
topology:
  guardian_pod: pod-guardian-01
preconditions:
  - "APP 已安装并冷启动"
  - "用户会话处于 expired 状态"
steps:
  - pod: pod-guardian-01
    method: mua
    action: |
      在 Guardian APP 中执行以下步骤:
      1. 冷启动 APP 到 entry screen
      2. 输入测试账号 ${test_account}
      3. 等待登录完成
      4. 验证 growth-home 页面显示 loaded 状态
      5. 触发下拉刷新
      6. 验证刷新后内容更新且无 loading 卡死
    assert:
      - "登录成功"
      - "growth-home 显示 loaded 状态"
      - "刷新后内容更新"
output_schema:
  Type: dict
  Fields:
    - Name: steps
      Type: list
      Fields:
        - Type: dict
          Fields:
            - Name: step
              Type: string
            - Name: passed
              Type: boolean
    - Name: passed
      Type: boolean
expected:
  passed: true
```
