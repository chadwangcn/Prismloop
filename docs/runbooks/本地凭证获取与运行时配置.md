# Prismloop 本地凭证获取与运行时配置

本说明覆盖 Prismloop 当前支持的所有本地/受管运行时凭证来源。凭证只用于调用火山引擎管理
OpenAPI，或为私有 vePhone Gateway 换取短期 SDK 会话；它们不是 `MediaRun` API 的输入。

禁止将 AK、SK、STS token、Pod 地址或永久签名 URL 提交到 Git、写入模板、测试 case、SQLite、
日志、截图、录屏和 SRE 回执。

## 来源与优先级

| 方式 | 适用环境 | 启用方式 | 代码路径 | 说明 |
|---|---|---|---|---|
| macOS Keychain | 开发者本机 | `credentials_source: keychain` | `src.credentials.load_credentials` | 本机首选；代码直接从 Keychain 读值，不在 shell 输出。 |
| 受管环境变量 | 14 / CI / 容器 | `credentials_source: env` | 同上 | 由 SRE Secret Manager、CI secret injection 或进程管理器注入；不写入 `.env` 或 unit 文件。 |
| 配置内凭证 | 隔离临时测试 | `credentials_source: config` | `src.config.load_credentials_from_config` | 仅兼容旧本地测试；严禁用于共享目录、仓库或 14。 |
| 短期 STS 会话 | 私有 vePhone Gateway | `PRISMLOOP_VEPHONE_STS_ROLE_TRN` | `src.volc_client_session.VolcClientSessionBroker` | 在内存中以 AK/SK 换短期 SDK token；浏览器不接收长期 AK/SK。 |

读取优先级为：完整的 `VOLC_AK` + `VOLC_SK` 环境变量优先；若两者都不存在，则读取 Keychain。
只设置其中一个变量会被拒绝。`config/env.local.json` 中 `credentials_source` 决定此策略由
`load_credentials_from_config` 如何调用。

## 1. macOS Keychain（开发机首选）

### 写入与检查

优先通过“钥匙串访问”创建两个 Generic Password 项，服务名由本机 `config/env.local.json` 的
`acep.ak_keychain_service` 与 `acep.sk_keychain_service` 指定。服务名本身不是秘密，可使用以下
占位示例：

```text
<YOUR_AK_KEYCHAIN_SERVICE>
<YOUR_SK_KEYCHAIN_SERVICE>
```

如必须使用 CLI，使用系统安全输入窗口或团队认可的秘密注入工具录入值；不要把真实值放在 shell
历史、脚本或命令行参数中。确认条目存在时可以让 Keychain 只返回元数据：

```bash
security find-generic-password -s '<YOUR_AK_KEYCHAIN_SERVICE>'
security find-generic-password -s '<YOUR_SK_KEYCHAIN_SERVICE>'
```

不要在普通终端运行带 `-w` 的查询——它会把秘密直接打印到标准输出。应用程序通过
`security find-generic-password -s <service> -w` 在子进程内读取值，但不会记录该值。

### 本地配置

`config/env.local.json` 只保存服务名与非秘密云资源引用：

```json
{
  "acep": {
    "credentials_source": "keychain",
    "ak_keychain_service": "<YOUR_AK_KEYCHAIN_SERVICE>",
    "sk_keychain_service": "<YOUR_SK_KEYCHAIN_SERVICE>"
  }
}
```

允许使用非秘密环境变量覆盖服务名，便于同一开发机隔离多个账号：

```bash
export VOLC_AK_KEYCHAIN_SERVICE='<YOUR_AK_KEYCHAIN_SERVICE>'
export VOLC_SK_KEYCHAIN_SERVICE='<YOUR_SK_KEYCHAIN_SERVICE>'
```

## 2. 受管环境变量（14、CI、容器）

由 SRE 的 secret manager/CI secret store 在**进程启动时**注入完整的一对变量：

```text
VOLC_AK=<injected-secret>
VOLC_SK=<injected-secret>
```

并在对应 `config/env.local.json`（或等价的只读部署配置）中声明：

```json
{"acep": {"credentials_source": "env"}}
```

不要执行 `export VOLC_AK=...`、`echo $VOLC_SK`，也不要把上述变量放入 shell profile、systemd
unit、Dockerfile、Compose 文件或部署脚本。SRE 应使用运行时 secret injection；应用只在内存中读取。

## 3. 配置内凭证（只为兼容，不推荐）

`credentials_source: config` 会读取 `mua.ak` / `mua.sk`。这只能用于一个开发者自己控制的、未同步的
短生命周期测试文件。不得在 `config/env.template.json`、`config/env.local.json`、Git 工作树、共享
磁盘或 14 环境使用。新环境必须选用 Keychain 或受管环境变量。

## 4. vePhone Gateway 的短期 STS 会话

`PRISMLOOP_VEPHONE_STS_ROLE_TRN` 是角色引用，不是 token。它由 SRE 仅配置在 14 的受管运行时中：

```text
PRISMLOOP_VEPHONE_STS_ROLE_TRN=<scoped-role-trn>
```

Harness 使用当前的 Keychain/受管 AK/SK 在进程内调用 `GetCallerIdentity`、`AssumeRole`，将短期
token 仅交给 loopback 私有 Gateway。不要将短期 token 写入文件、环境模板或回执。

使用下列命令进行脱敏验证；成功不输出账号、角色、Pod、端点或 token：

```bash
python3 scripts/preflight_vephone_client_gateway.py
```

成功输出：

```json
{"account_identity_resolved":true,"status":"ready","temporary_token_complete":true,"token_expiry_present":true}
```

未设置角色或权限不足时返回 `capability_unavailable`，这是预期安全闸门，不能用长期 AK/SK 绕过。

## 5. 安全的本地验证方式

以下命令只验证代码能否从已配置来源加载一对非空凭证；不会打印凭证内容，也不会请求云资源：

```bash
.venv/bin/python - <<'PY'
from src.config import load_config, load_credentials_from_config

credentials = load_credentials_from_config(load_config())
print({"credentials_loaded": bool(credentials.ak and credentials.sk)})
PY
```

预期输出为：

```json
{"credentials_loaded": true}
```

如需验证真实 STS 前置条件，使用上一节的 preflight；如需验证 ACEP 或媒体能力，必须使用 Harness
的独立 I/O 验收，而不能把凭证加载成功误认为云手机 PoC 成功。
